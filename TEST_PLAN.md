## 1. Integration Points Checklist

This section details the backend API endpoints and their conceptual mapping to frontend service functions.

### 1.1 Nacos Instance Management APIs

| Method | Path                                   | Purpose                                         | Key Request Payload Fields                                                                                              | Key Response Payload Fields (Success)                                                                                             | Frontend Service Function (Conceptual)             |
| :----- | :------------------------------------- | :---------------------------------------------- | :---------------------------------------------------------------------------------------------------------------------- | :-------------------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------- |
| POST   | `/api/nacos-instances`                 | Create a new Nacos instance entry.              | `instanceUrl`, `namespaceId` (optional), `description` (optional), `username` (optional), `password` (optional), `scheme` (optional), `contextPath` (optional) | `ID`, `InstanceURL`, `NamespaceID`, `Description`, `Username` (empty), `Scheme`, `ContextPath`, `CreatedAt`, `UpdatedAt`             | `api.createNacosInstance(data)`             |
| GET    | `/api/nacos-instances`                 | List all Nacos instance entries.                | None                                                                                                                    | Array of NacosInstance objects (password field cleared)                                                                          | `api.getNacosInstances()`                   |
| GET    | `/api/nacos-instances/:id`             | Get a specific Nacos instance by ID.            | Path param `:id`                                                                                                        | NacosInstance object (password field cleared)                                                                                    | `api.getNacosInstanceById(id)`              |
| PUT    | `/api/nacos-instances/:id`             | Update an existing Nacos instance.              | Path param `:id`; Same fields as POST, all optional. If `password` is empty, it's not updated.                          | Updated NacosInstance object (password field cleared)                                                                            | `api.updateNacosInstance(id, data)`         |
| DELETE | `/api/nacos-instances/:id`             | Delete a Nacos instance.                        | Path param `:id`                                                                                                        | `{"message": "Nacos instance deleted successfully"}`                                                                            | `api.deleteNacosInstance(id)`               |
| POST   | `/api/nacos-instances/:id/test-connection` | Test connectivity to the Nacos server.      | Path param `:id`                                                                                                        | `{"message": "...", "status": "successful/failed"}`                                                                             | `api.testNacosInstanceConnection(id)`       |
| GET    | `/api/nacos-instances/:id/namespaces`  | List all namespaces for a Nacos instance.       | Path param `:id`                                                                                                        | Array of Nacos Namespace objects (e.g., `[{ "namespace": "id", "namespaceShowName": "name", "type": 0 }]`)                     | `api.getNacosInstanceNamespaces(id)`        |

### 1.2 Configuration Management APIs

| Method | Path                                       | Purpose                                                              | Key Request Payload Fields                                                                                                                                 | Key Response Payload Fields (Success)                                                                                                                                                                                                                                                          | Frontend Service Function (Conceptual)                               |
| :----- | :----------------------------------------- | :------------------------------------------------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------- |
| POST   | `/api/configurations`                      | Create a new configuration entry in the local DB.                    | `nacosInstanceId`, `dataId`, `groupName`, `namespaceId` (optional), `content`, `contentType` (optional), `description` (optional)                               | `Configuration` object (includes `ID`, `MD5`, `CreatedAt`, `UpdatedAt`, etc.)                                                                                                                                                                                                                 | `api.createConfiguration(data)`                               |
| GET    | `/api/configurations`                      | List configurations from local DB.                                   | Query params: `nacosInstanceId` (optional), `namespaceId` (optional), `dataId` (optional), `group` (optional)                                              | Array of `Configuration` objects (NacosInstance preloaded, password cleared)                                                                                                                                                                                                                  | `api.getConfigurations(params)`                               |
| GET    | `/api/configurations/:id`                  | Get a specific configuration from local DB.                          | Path param `:id`                                                                                                                                           | `Configuration` object (NacosInstance preloaded, password cleared)                                                                                                                                                                                                                            | `api.getConfigurationById(id)`                                |
| PUT    | `/api/configurations/:id`                  | Update a configuration in local DB (saves content, creates history). | Path param `:id`; `content` (optional), `contentType` (optional), `description` (optional), `operator` (optional)                                            | Updated `Configuration` object                                                                                                                                                                                                                                                                | `api.updateConfiguration(id, data)`                           |
| GET    | `/api/configurations/:id/diff-nacos`       | Get diff between local DB version and Nacos version.                 | Path param `:id`                                                                                                                                           | `{"diff": "...", "localContent": "...", "nacosContent": "...", "isDifferent": boolean, "nacosError": "..." (optional)}`                                                                                                                                                                 | `api.getConfigurationDiffWithNacos(id)`                       |
| POST   | `/api/configurations/:id/fetch-from-nacos` | Fetches config from Nacos and updates local DB.                      | Path param `:id`; Query param: `operator` (optional)                                                                                                       | Updated `Configuration` object (content from Nacos, new `MD5`, `LastSyncTime`, new history entry created)                                                                                                                                                                                     | `api.fetchConfigurationFromNacos(id, operator)`               |
| GET    | `/api/configurations/:id/history`          | List history versions for a configuration.                           | Path param `:id`                                                                                                                                           | Array of `ConfigurationHistory` objects                                                                                                                                                                                                                                                       | `api.getConfigurationHistory(configId)`                       |
| GET    | `/api/configurations/history/:historyId`   | Get a specific historical version's content.                         | Path param `:historyId`                                                                                                                                    | `ConfigurationHistory` object (Configuration.NacosInstance preloaded, password cleared)                                                                                                                                                                                                       | `api.getConfigurationHistoryEntry(historyId)`                 |
| POST   | `/api/configurations/:id/rollback/:historyId` | Rollback config to a specific history version.                   | Path params `:id`, `:historyId`; `operator` (optional)                                                                                                     | Updated `Configuration` object (content matches history entry, new history entry created for rollback action)                                                                                                                                                                                     | `api.rollbackConfiguration(configId, historyId, payload)`     |
| POST   | `/api/configurations/:id/publish`          | Publish a configuration to Nacos.                                    | Path param `:id`; `publishType` ("FULL", "GRAYSCALE" - though grayscale might be limited), `operator` (optional)                                             | `{"message": "...", "publishRecord": PublishRecord object}`. Configuration's `LastSyncTime` and `LastSyncVersion` are updated. A `PublishRecord` is created/updated. | `api.publishConfiguration(configId, data)`                    |

Introduction
This document outlines the test plan for the Nacos Configuration Management tool. It provides a comprehensive overview of the testing strategy, scope, and approach for the project.

## 2. Test Objectives
The primary objectives of testing the Nacos Configuration Management tool are:
- To ensure the tool correctly implements all specified requirements.
- To verify the stability and reliability of the tool under various conditions.
- To identify and report any defects or issues found during testing.
- To ensure the application meets performance and usability standards.

## 3. Scope

### 3.1 In Scope
- Nacos instance management (CRUD operations, connection testing, namespace fetching)
- Configuration management (create, read, update, delete configurations, diff, fetch, publish)
- History and record viewing (configuration history, publish records)
- Error handling and user feedback

### 3.2 Out of Scope
- Performance testing under extreme load conditions (beyond typical use cases)
- Security testing beyond basic authentication and authorization
- Integration with external systems not explicitly mentioned in the API documentation

## 4. Test Strategy

### 4.1 Testing Levels
- **Unit Tests:** Focus on individual components and functions.
- **Integration Tests:** Test interactions between different components of the application.
- **End-to-End (E2E) Tests:** Simulate real user scenarios from the frontend UI to the backend and Nacos server.

### 4.2 Testing Types
- **Functional Testing:** Verify the core functionalities as per user stories.
- **Usability Testing:** Assess the ease of use and user-friendliness of the UI.
- **Compatibility Testing:** Ensure the tool works across different browsers and operating systems.
- **Error Handling Testing:** Validate how the application handles invalid inputs and error conditions.

### 4.3 Test Environment
The test environment will consist of:
- **Backend:** Go application running locally.
- **Frontend:** Vue.js application running locally.
- **Database:** MySQL database, either local or Dockerized.
- **Nacos Server:** Local or Dockerized Nacos instance.
